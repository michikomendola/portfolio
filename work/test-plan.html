Sample test plan

Fictional checkout feature · written in the format I use with engineering teams

1. Objective

Confirm that a guest and a signed-in shopper can complete checkout, that tax and totals stay correct, and that failed payments do not create a paid order.

2. In scope

  • Cart → shipping → payment → confirmation
  • Promo code apply / remove
  • Card success, card decline, and timeout

3. Out of scope

  • Warehouse fulfillment after confirmation
  • Admin refund tools (covered in a separate pack)

4. Risk

Highest: double-charge on retry, tax rounding, and confirmation email with the wrong total. Those cases are blocking for release.

5. Approach

Scripted cases for money paths; 90-minute exploratory charter on mobile Safari for layout and session restore. Cypress smoke on login + add-to-cart if the build is stable.

6. Exit criteria

  • No open Sev-1 / Sev-2 on checkout
  • 100% of P1 cases executed; P2 ≥ 90%
  • Product owner sign-off on UAT notes

7. Sample cases

ID Title Priority Expected
CHK-01 Happy path, saved card P1 Order ID shown; cart empty; email queued
CHK-02 Declined card P1 No order; user can retry; no inventory decrement
CHK-03 Promo then remove P2 Totals revert to original subtotal + tax
