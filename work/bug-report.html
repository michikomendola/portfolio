Checkout charges twice when the user double-clicks Pay

ID DEMO-1842
Severity Sev-1 · Blocker
Environment Chrome 128 · Staging · build 2026.09.04
Component Checkout / Payments

Summary

Tapping Pay twice in under one second creates two captured transactions and two order IDs for a single cart.

Steps to reproduce

  1. Log in as qa.shopper+doublepay@example.com.
  2. Add SKU TEE-NAVY-M (qty 1) and proceed to checkout.
  3. Use test card 4242 4242 4242 4242, any future expiry, CVC 123.
  4. Click Pay now twice quickly (or press Enter twice).

Expected

The Pay button disables after the first click. One payment intent. One order.

Actual

Two payment_intent.succeeded events fire. Confirmation page shows order ORD-99102; email shows ORD-99103. Wallet ledger has −$48.00 twice.

Notes

  • Does not reproduce if the second click is more than ~1.5s later.
  • Network tab: two POST /api/checkout/confirm with different idempotency keys.
  • Suggested fix: button lock + server idempotency key tied to cart ID.
